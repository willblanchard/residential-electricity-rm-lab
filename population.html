How WTP drives elastic vs inelastic behavior

Nathan's WTP work anchors the source demand data at 10 cents per kWh. The dashboard then re-indexes that curve to the 18 cent flat-rate baseline so the population model can separate price-insensitive customers from customers with discretionary load that responds to price signals.

Source WTP anchor 10.0¢ Nathan's MATLAB work uses this as the assumed price for the demand data.
Dashboard reference 18.0¢ = 100% The browser model normalizes demand at the flat-rate baseline used in the class story.
High-price signal 30.0¢ = 77.2% The WTP curve implies materially lower demand as effective price rises.
Bounded range 72%-118% The WTP page caps extreme expansion or contraction for presentation-safe scenarios.

Why this population exists

The portfolio is designed to separate three effects that are easy to mix up: human price response, automated device response, and rate-menu choice. Single Price Results uses the population as a fixed mix; Parallel Options Results then asks which customers leave the fixed pool when optional plans are offered.

Same base Flat, TOU, and demand-charge cases all start from this population.
Controllable mix The Single Price Results allocation controls can stress-test the shares without redefining the buckets.
Choice is separate Opt-in behavior belongs to Parallel Options Results, not the baseline population definition.
